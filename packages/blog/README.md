# KK Trip CMS and blog

The Astro 6 blog now embeds EmDash 1.1 as a dependency. Public routes retain the
KK Trip design; the admin is at `/_emdash/admin/`. The legacy FlareCMS packages
remain available for rollback, but the blog no longer calls their API.

## Development

Use the workspace's pinned pnpm 12.9.1 and Node 22.16 or later:

```sh
pnpm install --frozen-lockfile
pnpm --filter @flare-cms/blog dev
```

From `packages/blog`, generate a local encryption key with
`pnpm exec emdash secrets generate --write .env`. Never commit `.env`, `.dev.vars`,
or private exports. Keep a protected backup of the key.

## Migration

Three published posts are included in `seed/seed.json`. Their slugs, bylines, tags,
and original publication/update dates are preserved. Drafts are deliberately
excluded from the public seed. The Flare exporter (`pnpm migrate:flare`) is a one-time migration tool that
replaces the seed; do not run it against the adopted template seed. Use EmDash
exports to back up current content and editorial configuration. The exporter rejects unsupported article blocks instead of silently
losing their contents. Review new block support before publishing those blocks.

The seed converts HTML to Portable Text. Remote featured and inline images use `$media`
references so EmDash copies them into its own storage during seed application.
Embedded base64 images are extracted to `public/migrated-media/` and served
with the site. Verify every image after import; keep the old CMS reachable until those copies
are complete. Content in linked external URLs is not copied automatically.

## Production

The production Worker is `kktrip-emdash`, with its own `kktrip-emdash-db`
and `kktrip-emdash-media` resources. The original `kktrip-blog` deployment
and FlareCMS resources remain available for rollback. Its pre-cutover version
is `7a228754-8bfe-48f6-b1d6-8c375f1836d4`. To roll back public traffic, assign
the `news.kktrip.app` custom domain back to `kktrip-blog`; keep both databases
and all media buckets intact.

Deploy with `pnpm deploy` after verification. Keep `EMDASH_ENCRYPTION_KEY` and
`KKTRIP_SETUP_KEY` as Worker secrets. Protected local backups live under the
ignored `.emdash/` directory and must never be committed.

First administrator setup is protected by `KKTRIP_SETUP_KEY`. The private
setup link exchanges the key for a secure, HttpOnly cookie valid for one hour.
Open that link on `news.kktrip.app` and complete passkey registration yourself.
Normal authenticated administration uses EmDash's own passkey sessions.
The protection remains enabled for setup/recovery routes after registration.

The seed import copies remote media into R2. Check all articles, original dates,
RSS, and images after deployment before switching the custom domain.
Production schema migrations run on the first request; content is imported by
the protected setup endpoint. The old unpublished draft stays in FlareCMS.

GitHub Actions validates changes; production deployments are explicit.

## Checks

```sh
pnpm --filter @flare-cms/blog lint
pnpm --filter @flare-cms/blog test
pnpm --filter @flare-cms/blog seed:validate
pnpm --filter @flare-cms/blog check
pnpm --filter @flare-cms/blog build
```

Run Worker-backed checks sequentially: they share the local D1 simulation.
Generated Worker binding/runtime types are ignored and regenerated by `check`.

## Editorial template features

The public site uses native EmDash menus, widgets, taxonomies, bylines, search,
pages, sections, and SEO metadata while keeping KK Trip's Tailwind design.

- Menus: `primary` controls the header; `footer` controls footer links.
- Widgets: `sidebar` appears on article listings; `article-sidebar` appears beside
  articles on desktop; `footer` appears in the footer. Defaults include search,
  categories, recent posts, and an app link.
- Categories and tags: manage assignments in the article's native panels.
  Category URLs are `/category/{slug}`; tag URLs are `/tag/{slug}`. Existing tag
  labels and article URLs remain valid.
- Bylines: assign one or more authors, their avatar, and credit role. The imported
  articles use the KK Trip editorial byline. Legacy import fields are unused.
- Pages: publish content from the Pages collection at `/pages/{slug}`. Add the
  page URL to a menu to expose it in navigation. Drafts require a signed preview.
- Sections: insert the reusable `plan-with-kktrip` section through the content
  editor. Sections insert a copy of their blocks; later section edits affect future
  insertions, so review existing copies separately.
- Search: `/search` searches published posts and pages. Search results are not
  indexed by search engines.
- SEO: article and page SEO settings feed native EmDash head metadata. Redirects
  continue to use EmDash's existing redirect middleware.

For an existing installation, back up D1, then apply the one-time editorial
migration before deploying the application:

```sh
pnpm exec wrangler d1 time-travel info kktrip-emdash-db
pnpm exec wrangler d1 execute kktrip-emdash-db --remote --file migrations/20261006_template_adoption.sql
```

Record the recovery bookmark privately before applying the migration. D1 full
exports do not support the FTS5 tables used by search; use a protected logical
content export in addition to Time Travel when needed. Keep exports private. The migration preserves article bodies and dates,
adds missing defaults, and converts the three imported articles' tags and author
fields to native relationships. Reapplying it does not duplicate defaults.
Fresh installations use `seed/seed.json`; `seed/template.json` is the structure
source used to generate the migration. Existing menus and widget areas win over
seed defaults.
