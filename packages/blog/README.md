# KK Trip CMS and blog

The Astro 6 blog now embeds EmDash 1.1 as a dependency. Public routes retain the
KK Trip design; the admin is at `/_emdash/admin/`. The legacy FlareCMS packages
remain available for rollback, but the blog no longer calls their API.

## Development

Use the workspace's pinned pnpm 12.9.1 and Node 22.16 or later:

```sh
pnpm install --frozen-lockfile
pnpm --filter @flare-cms/blog dev
```

From `packages/blog`, generate a local encryption key with
`pnpm exec emdash secrets generate --write .env`. Never commit `.env`, `.dev.vars`,
or private exports. Keep a protected backup of the key.

## Migration

Three published posts are included in `seed/seed.json`. Their slugs, bylines, tags,
and original publication/update dates are preserved. Drafts are deliberately
excluded from the public seed. Before cutover, refresh the export from the live
CMS by running `pnpm migrate:flare` in this package (or pass a private JSON export
path). The exporter rejects unsupported article blocks instead of silently
losing their contents. Review new block support before publishing those blocks.

The seed converts HTML to Portable Text. Remote featured and inline images use `$media`
references so EmDash copies them into its own storage during seed application.
Embedded base64 images are extracted to `public/migrated-media/` and served
with the site. Verify every image after import; keep the old CMS reachable until those copies
are complete. Content in linked external URLs is not copied automatically.

## Preview and cutover

The checked-in Wrangler config targets `kktrip-emdash-preview` with a separate
`kktrip-emdash-preview-db` and `kktrip-emdash-preview-media` bucket. It has no
production custom-domain route. Wrangler provisions these named resources on
first deployment. Core schema migrations run on the first request.

1. Build and dry-run packaging: `pnpm build`, then `pnpm exec wrangler deploy --dry-run`.
2. Deploy the preview with `pnpm exec wrangler deploy` and configure
   `EMDASH_ENCRYPTION_KEY` as a Worker secret using protected input.
3. Complete setup at `/_emdash/admin/`, register your passkey, and select the
   migrated seed content. Check the three posts, dates, tags, RSS, and images.
4. Create/edit/publish a test post and confirm saved drafts stay private.
5. After preview approval, set the production site URL and custom-domain route
   for `news.kktrip.app`, and register a passkey on that final origin. Passkeys
   from the preview origin do not automatically work on the production origin.
6. Keep the old FlareCMS Worker and database until the migration is verified.

GitHub Actions runs validation only; the upstream FlareCMS auto-deployment
workflow was replaced to avoid deploying the upstream documentation site.
Production DNS and existing resources are not changed by pushing this branch.

## Checks

```sh
pnpm --filter @flare-cms/blog lint
pnpm --filter @flare-cms/blog test
pnpm --filter @flare-cms/blog seed:validate
pnpm --filter @flare-cms/blog check
pnpm --filter @flare-cms/blog build
```

Run Worker-backed checks sequentially: they share the local D1 simulation.
Generated Worker binding/runtime types are ignored and regenerated by `check`.
